# analysis/ (release v1.1.0)

Analysis code of "Material-dependent positronium lifetimes in GATE and prompt-selection bias" (Dhar and Peter, PMB).

## Purpose

This folder is the **as-run subset** of the analysis tree that produced the numbers of the paper: every script of
the result inventory (Secs. 3.1 to 3.6 and the Methods numbers), every module those scripts import or `exec`, the
published output JSON/CSV of each result, and the intermediate histograms (npz) from which most results can be
recomputed without the raw simulation output. Nothing was refactored. The scripts are byte-identical to the files that
ran, except for path handling (hard-coded absolute paths replaced by environment variables with release-relative
defaults) and the wording and punctuation of comments. Every changed line is listed in `EDITS.md`, generated by diffing against the source tree. Three scripts were
missing from the source tree and were written for this release (marked **new** below). Their outputs reproduce the
published JSONs (see "Regression").

## Layout

The folder mirrors the project tree, so the dated folder names and file names are the ones cited in the lineage files:

| release path | project path |
|---|---|
| `results/<dated folder>/...` | `reconstruction/results/<dated folder>/...` |
| `reconstruction/` | `reconstruction/` (triples extraction, TOF filter, travel-time correction) |
| `pli-quadra-archive-2026-08-12/` | archive copy of `per_insert_hypoxia.py` (oxygen table), the only copy that exists |
| `results/methods/` | **new**: `seed_factor.py` |
| `legacy_v1.0.1/` | `pedestal.py`, `tao_eldrup.py` of release v1.0.1, unchanged (superseded, kept for reference) |

Scripts write their outputs next to themselves (as they did when they ran), so running a script in place overwrites the
shipped JSON. Copy the folder first if you want to compare (this is how the regression below was done).

to the system interpreter). Multiprocessing scripts start 8 to 24 workers.

## Environment variables

| variable | meaning | default |
|---|---|---|
| `PLI_RES` | results tree (replaces `.../reconstruction/results`) | this release's `analysis/results`, resolved from each script's own location |
| `PLI_REPO` | repository root (for `materials/pli_materials.json`) | the release root (`pli-gate-1.1.0/`) |
| `PLI_RAW` | folder with the raw simulation output (not in the release, see below) | unset: every read of a raw file stops with `raw data not included in the release, see analysis/README.md` |
| `PLI_FIGOUT` | output folder of `figsrc/common.py` (figure generator) | `results/2026-09-30_referee2/figs/out` |

Code imports never depend on these variables: `sys.path` entries point into `analysis/` relative to each script.
Note on `PLI_REPO`: the release `materials/pli_materials.json` is database v8 (sha256 23f607ea... as used, see
`materials/PROVENANCE.md`), the one used by
the oxygen chain (`per_insert_hypoxia.py`) and by `make_r2c_materials.py`. The closure (rows 1, 2) ran with database
2a26b68e... (`analyze_per_tube_tau.py` defaults to the repository database). The configured lifetimes of the twelve
closure tubes are the same in both, but to rerun the closure exactly pass `--materials-json` with that database (flag F9).

Running a script: `cd` into its folder and run `python3 <script>.py` with the arguments given below (several scripts
read or write paths relative to the working directory: `plateau_c0.py`, `excess_shape.py`, `excess_mean.py`,
`v2_context.py`, `b5_water.py`, `b3_fit.py`).

## The new scripts

* `results/methods/seed_factor.py`: chi2 = sum over tubes and seeds of (tau - seed mean)^2 / (tau / sqrt(n))^2 = 27.150
  for 16 dof, factor sqrt(27.15/16) = 1.30, 95 % interval from the chi2(16) quantiles 0.97 to 1.98, mean seed spread
  0.80 % against 0.67 % counting, ratio of means 1.20. The printed 27.2 corresponds to deviations from the plain seed
  mean. With the inverse-variance weighted mean the sum is 27.137 (27.1). Factor and interval are unchanged.
* `results/2026-10-19_review16/shard_independence.py`: genuine triples of C0 (all prompts, k = 1), sharp-edge windowed
  moment, counting sigma = sqrt(var/n) / (dm/dtau), shard bootstrap B = 1000 with seed 1, half split even against odd
  shards with z = (tau_even - tau_odd) / (2 sigma). Reproduces every field of the published JSON exactly.
* `results/2026-10-19_review16/water20cm/w20_apriori.py`: sigma_geo 303.87 / 344.11 / 306.09 ps with one generator
  (seed 20261019) in the order 20 mm, 20 cm, sigma_geo.py geometry, sigma_e 350.06 ps. All-prompts readout from
  `w20_edge_hists.npz` (the production all-prompts subset, identical to the w20_extract histograms in the fit window).
  The closest-prompt point value comes from the windowed mean recovered from the stored sharp readout, because the
  closest-prompt histograms were not kept. Its uncertainty needs the raw batches (pass them as arguments).

## Timing-smear seeding (two schemes, flag F5)

The 90.9 ps single-photon smear of the clinical builder is drawn from `numpy.random.default_rng`:

* **sequential**: one generator `default_rng(90900)` (= `int(sigma_t_ps * 1000)`), drawn shard after shard in file order
  (`clinical_run` of `sim1_extract.py`, `steinberger_extract_ap.py`, `nema_extract.py`, and `dump_shard_hists.py`,
  `steinberger_acceptance(_o4).py`, `nema_acceptance.py`, `w20_extract.py`, `w20_edge.py`, `measure_oversubtraction.py`,
  `pair_window.py`, `builder_sensitivity.py`, `factorization_test2.py`). Feeds: `hists_c0_0ps.npz` (Fig. 4, rows 19-21:
  closest 17.94 %, all prompts 6.65 %), `c0_compare.json` (retention, rows 30, 33, mu), `hists_sim1_388.npz` (row 31),
  `hists_{sim1,nema,disks,water}.npz` and `signed_eq3.json` (pedestal regression, row 21, rate rows 35), Table 5
  (rows 3-8), the benchmark (`hists_mercolli.npz`, row 9), over-subtraction (row 18), sorter windows (rows 23, 38),
  factorization (row 26), builder sensitivity (S18).
* **per shard**: `default_rng([90900, shard_id])`, independent of the processing order (`photon_conventions_c0.py`,
  `known_randoms_c0.py`, `known_randoms_c2.py`, `rules16.py`, `ladder_joint_c0.py`, `prompt_path_test.py`, while
  `crt_sweep_c0.py` uses `[round(sigma_ps * 1000), shard_id]`, whose 90.9 ps arm equals `photon_conventions.npz`). Feeds:
  Fig. 3 and Sec. 3.4 (rows 15, 16, 24: closest 17.98 %, all prompts 6.70 %, a priori 1.9 %), known content (rows 25,
  26, 32), rules and rate law (rows 22, 27, 28, 34, 36-38), `radius410.json`, `shard_independence.json`, S24.

The two schemes are two realizations of the same smear of the same C0 events. Their difference (17.98 against 17.94 %,
6.70 against 6.65 %) is the smear-realization spread, not a code difference.
